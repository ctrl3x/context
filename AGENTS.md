# AGENTS.md

## Что это за проект

Одностраничный лендинг-скроллителлинг **«Как медиа искажают исследования»** (учебный проект НИУ ВШЭ). Статический сайт без сборки и зависимостей: чистые HTML + CSS + vanilla JS. Страница — цепочка «экранов» фиксированного размера с пинами, скрабом по скроллу и анимированными переходами. Дизайн переносится из Figma-макета. Есть вторая, **мобильная** версия (`mobile.html`) — статичный вертикальный лонг-рид без пинов: единственный JS — масштаб и fade-гейты на границах экранов (титульная последовательность фраз — на тёмном экране `m-quest`); правила синхронизации версий — в «Конвенциях».

## Как запустить

Статики достаточно открыть в браузере, но из-за `history.scrollRestoration` и hash-навигации лучше локальный сервер:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

Сборки, линтеров, тестов, package.json нет — ничего не устанавливается и не билдится.

```

css/style.css            — все стили (~1100 строк), секции помечены комментариями /* ---------- N. НАЗВАНИЕ ---------- */
js/scale.js              — масштабирование страницы под вьюпорт ( design 1280×832 → scale )
js/hero.js               — герой: пошаговое появление виджетов по wheel/keys + пин «Учёные доказали…» со скрабом
js/cards.js              — карточки 01–04: «лента»-переходы + пин фото-руки; переход 04 → «Учёные доказали» — два пина с общим FADE, синхронен с js/scientists.js (зона/порог/почему — LOG.md)
js/teardown.js           — разбор поста: пин с табами ПУБЛИКАЦИЯ → КОНТЕКСТ → ПЕРВОИСТОЧНИК → ВЕРДИКТ
js/checklist.js          — тикер чек-листа: правая скобка ездит по зафиксированной левой и «печатает» «КОНТЕКСТ» побуквенно; пока экран в кадре — пульс (сжатие/раскрытие), класс .in по IntersectionObserver; катыш-шарик (.cl-ball) катится по «хребту» checklist.svg от позиции скролла — svg виден выше шарика, ниже скрыт (clip-path инлайном); у стыка с экраном «Вывод» шарик растворяется на хвосте линии
js/check.js              — катыш экрана «Проверять — значит видеть картину целиком» (sec-check, не пинится): шарик (.cl-ball, чёрный) по «хребту» check.svg — svg виден выше шарика, ниже скрыт; граница привязана к пересечению вьюпорта (скорость 2/3, как у соседних катыши), шарик появляется из-под экрана «Не спешите верить заголовку…» и растворяется на последних 150px хребта — тот кончается в воздухе (546.5;806)
js/decor.js              — экран «Наука стала декорацией» + финал: катыши по decor_dark/finale_lines.svg, на стыке «инверсия цвета»; высоту пина финала ставит syncPin (нельзя хардкодить; подробности — LOG.md)
js/sides.js              — фон body за пределами колонки (белый/чёрный по текущей секции)
js/scientists.js         — «фонарик» на панели «Учёные доказали» + ручной пин; на хвосте — разворот маски в фулскрин «вопросы» (скролл переключает состояние, анимация фиксированная, всем рулит var --p); FADE синхронен с js/cards.js, темноту хвоста sides.js узнаёт через событие 'sciexp' (подробности — LOG.md)
js/tdgates.js            — гейты разбора поста: оба стыка секции «Учёные доказали: [X]» — вход с фулскрина «вопросы» и выход с вердикта на чек-лист — через белую вуаль в обе стороны (как fadeForward/fadeBack). Колесо/клавиши перехватываются на статичных участках по сторонам 832px слайдов (стоянка «вопросов», запас вердикта), проскок в слайд ловит fallback на scroll с мгновенным укрытием; геометрию пинов не трогает
figma_group_screen1.js   — разовый скрипт для консоли Figma (группировка слоёв экрана 1779:572), к сайту не подключён
mobile.html              — МОБИЛЬНАЯ версия: статичный лонг-рид по мокапу 1972:766, 10 секций суммарной высотой 15964px (координаты — inline-style, локальные внутри секций; декор — поэкранный inline-SVG .m-decor)
css/mobile.css           — стили мобильной версии: примитивы .m-* (m-pill, m-widget 278px, m-tick, m-pill-lg, m-pg), фоны/высоты секций — по мокапу
js/mobile.js             — TikTok-механика скролла: wheel/touch обрабатываются сами (preventDefault), нативный скролл и инерция выключены — «разогнать» и проскочить экран нельзя; один жест = один шаг (внутри экрана палец/колесо ведут 1:1 без доводки), гейт поглощает жест целиком. Гейты на всех границах со сменой цвета фона, в обе стороны (как fadeForward/fadeBack на десктопе): соседние секции одного цвета фона — один экран (statement+card, sci+list), на границе через белую вуаль (250/400 мс) страница подменяется следующим экраном; если экран короче вьюпорта, стоп-позиция прижимается к его верху. Масштаб: s = clientWidth/414, высота #m-page = inner.offsetHeight×s; пересчёт на resize/load/fonts.ready. На входе в m-quest поверх гейта фразы по очереди выплывают по центру (600/1400/400 мс, первый раз — фраза → вопрос, повторный вход сверху — вопрос сразу; при возврате снизу вверх экран «отматывается»: вопрос гаснет и фраза выплывает снова)
assets/svg/, assets/img/ — декоративные линии-коннекторы, скриншоты, фото
proof/, *.png            — скриншоты-референсы макета (не часть сайта); proof/mobile-spec.txt — читаемая спека мобильного мокапа, proof/mobile-1972-766.json — структурированная выкачка (источник координат/текстов)
LOG.md                   — журнал решений (новое сверху): «почему так», магические числа, отвергнутые варианты; читайте перед нетривиальными правками, дописывайте после значимых изменений
```

## Ключевые концепции (важно понимать до правок)

1. **Дизайн-канва 1280×832.** Каждая секция `.sec` — ровно один «экран» 1280×832 px. Позиции элементов заданы в координатах макета (часто inline-style). Адаптива нет: вся страница масштабируется целиком через `transform: scale()` в `js/scale.js`.
2. **`scale()`-фактор.** Реальный масштаб = `#page-inner` ширина / 1280. Любые вычисления скролла (`pinTop`, пороги) умножаются на него. При изменении размеров/пинов держите это в голове.
3. **Двойной путь анимаций.** Современные браузеры — CSS scroll-driven animations (`animation-timeline: scroll(root)`, класс `.tl`); старые — JS-скраб на rAF/scroll (класс `.no-tl` / fallback-ветки). Логика порогов в обеих ветках должна совпадать.
4. **Пины.** Секции-пины (`statement-pin`, `cards-pin`, `td-pin`, `fin-pin`) «залипают» на N px скролла. Скролл управляет **состоянием**, но сами переходы играют с фиксированной длительностью — скоростью скролла не рулить. Высоту `fin-pin` (пин финала в js/decor.js) нельзя хардкодить: она зависит от высоты вьюпорта и пересчитывается в syncPin.
5. **Перехват wheel/keydown.** `hero.js` и `cards.js` перехватывают `wheel` (`passive: false`) и стрелки/Пробел, сами решают: пошаговое состояние, анимация-«лента» или нативный скролл. Дебаунс `gate()` ≈ 250 мс.
6. **Превью-хэши.** Состояния можно смотреть без скролла: `#hero-step1..4`, `#card-step1..4`, `#sci-step1` (экран «Учёные доказали»), `#sci-step2` (фулскрин-экран вопросов), `#td-step0..3`. Эти хэши также отключают автоскролл-восстановление при перезагрузке; прыжок повторяется после `load`/`document.fonts.ready` — web-шрифты меняют layout позже загрузки.

## Конвенции

- Всё содержимое на русском; код-комментарии тоже на русском, они объясняют **почему** (частые ловушки: дробные пиксели от scale, границы зон скролла, порядок слоёв Figma). Сохраняйте стиль таких комментариев.
- Классы короткие и «дизайнерские»: `.sec`, `.pill`, `.widget`, `.td-*`, `.cl-*` (checklist), `.card-*`, `.concl-*`. Новым блокам давайте префикс по секции.
- Типографика: `IBM Plex Mono` — заголовки/подписи, `Arsenal` — текстовые абзацы; классы `.h40`, `.lead20`, `.lead18`, `.body16`, `.caps`, `.med`.
- Палитра только из CSS-переменных: `--black`, `--white`, `--orange` (#fc6030), `--red` (#ff3c00), `--gray`.
- Абсолютное позиционирование внутри `.sec` — норма для этого проекта; не пытаться «переводить на флексбокс» без необходимости.
- Скрипты — IIFE без глобалов, подключаются в конце `body` в порядке: scale → hero → cards → teardown → checklist → check → decor → sides → scientists → tdgates.
- Мобильная версия (`mobile.html`, префикс классов `.m-*`) повторяет тексты десктопа, но статична (без пинов; единственный JS — `js/mobile.js`: TikTok-механика скролла без нативной инерции, fade-гейты на границах экранов и титульная последовательность `m-quest` — фразы выплывают по центру, позиции сознательно отклоняются от мокапа, см. комментарий в `mobile.html`). Текстовые правки вносите **синхронно в обе версии**; эталон координат/текстов мобильной — `proof/mobile-spec.txt` и `proof/mobile-1972-766.json` (мокап Figma 1972:766, канва 414). Редиректы: `index.html` → `mobile.html` при `max-width: 767px`, обратно при `min-width: 768px`; проверка только при загрузке, «переключения на лету» нет.

## Правила работы для агента

- **Минимальные правки.** Проект хрупкий: пороги пинов, границы зон и fallback-ветки завязаны друг на друга. Меняя одну секцию, проверьте соседние переходы (wheel вверх/вниз по всей странице).
- Журнал решений: перед нетривиальными правками прочитайте записи `LOG.md` по затронутым секциям (там «почему так» и отвергнутые варианты); после значимого изменения добавьте запись — ≤5 строк: что / почему / отвергнуто / файлы.
- Лог держите компактным: когда вывод записи стал общим правилом, он переезжает в этот файл или в комментарий в коде, а запись в `LOG.md` ужимается; потолок ~20–30 записей, старое удаляется.
- Проверяйте изменения в браузере при поддержке и отсутствии scroll-driven animations (Chrome и старый Safari/Firefox), а также preview по hash-шагам.
- Не трогайте `figma_group_screen1.js`, `proof/`, `*.png` в корне — это референсы/инструменты для Figma, не сайт.
- Не добавляйте сборку, фреймворки и зависимости — проект намеренно dependency-free.
- Изображения с прозрачностью (photo-hand.png, scheme.png, article.png) используются как контент слоёв — при замене сохраняйте размеры в координатах макета.
